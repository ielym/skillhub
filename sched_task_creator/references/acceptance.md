# 交付验收清单

交付前逐项确认。任一条不满足 = 不通过。

## 生产者

- [ ] 常驻；发现工作与调度器解耦（调度器停止/库不可写时仍持久化+发布）。
- [ ] 先持久化「游标 + 待发布记录」同一原子写，再原子发布正式 JSON，成功后才标记已发布。
- [ ] 作业标识由（任务标识 + 稳定事件标识 + 业务版本）确定，重放得到同一 job_id。
- [ ] 重启可重放未确认作业并补扫（recovery 字段如实说明保留/回放/遗漏识别）。

## 执行者

- [ ] 继承 `ExecutorTask`，注入 `SCHED_*` 环境变量下运行。
- [ ] 进展事件上报单调递增已完成单元数（`completed_units`）；存活由 SDK 自动心跳判定（任务无需自行实现心跳）。
- [ ] 若使用断点：检查点原子写、含格式版本/输入标识/业务版本/进度/提交编号（断点是任务可选实践，不强制）。
- [ ] 幂等提交：稳定幂等键 + 可核实提交记录；重复执行未确认单元不产生重复有效结果。
- [ ] 资源错误有限重试（R3）：单次外部操作失败后原地重试最多 2 次（固定 3s 间隔，重试落日志），耗尽仍失败立即报 `error` 事件并 exit 75；禁止无界重试/兜底/跳过/长等待；reason 携带错误类型（异常类名/状态码）与资源标识（URL/主机）；业务逻辑错误不冒充资源不足；凭证/账号类敏感信息不写入 reason。
- [ ] 永久不可得的目标单元（4xx 类目标缺失/被拒）单独跳过并记录，不阻塞整体、不报资源不足。
- [ ] 长等待用 `wait_interruptible()`（可中断），不用死 `sleep`——收到暂停立即在安全边界响应。
- [ ] `execute()` 正常返回不等于完成：完成必须显式 `complete()` 提交完成记录。
- [ ] 退出 0 必提交 `done` 完成记录。
- [ ] 协作暂停：收命令 → 停新工作 → 保存断点（若有）→ 发 ack → 退出；暂停命令身份不匹配（残留旧命令）时忽略。

## 配置与自包含

- [ ] `task.json` 无运行上限/排队上限/资源申请；`priority` 合理。
- [ ] 任务目录自包含（producer.py + run.py + 配置），不共享业务代码。
- [ ] 运行参数写在就绪 JSON 引用的配置文件里，不用 job_id 文件名反推。
- [ ] 本地不记录外部资源（接口/账号/隧道/配额/资源指纹）。

## 行为验收

- [ ] `sched task validate <id>` 通过。
- [ ] `sched serve` 后生产者存活、作业从 QUEUED → RUNNING → SUCCEEDED（或长期任务持续进展）。
- [ ] 暂停演练：PAUSING → PAUSED，恢复后从最近检查点续跑不重复已完成工作。
- [ ] 不足演练：exit 75 → BACKOFF，恢复后继续。
- [ ] 取消演练：`job cancel` 后作业立即持久化 CANCELLED；调度器崩溃/重启后不复活已取消作业。
- [ ] 重启演练：`serve` 重启后 RUNNING 作业经 RECOVERING 核实 → 按检查点重放续跑；生产者单实例锁接管、不重复拉起。
- [ ] 进程树回收：取消/暂停后整个执行进程树退出，无孤儿。

## 能力边界（明确保留，不通过加隐含上限改变约束）

- 纯执行侧观测不能完全覆盖机器上其他程序的竞争。
- 没有资源身份不能精确识别跨任务争用。
- 动态探索不能保证第一次启动永不超载。
- 任务不丢失依赖生产者持久化 + 数据源可回放；业务结果不重复依赖检查点 + 幂等提交。
