# 铁律与交付红线

## 铁律详解（H1–H14）

### H1 唯一执行通道
正式执行只能由调度器扫描 outbox 就绪 JSON 触发。禁止 cron、手工跑、自触发执行进程。原因：绕过调度器即失去资源协调、动态目标、保护退让与断点恢复保证。

### H2 生产/执行分离
生产者进程与执行进程分属不同管理范围。禁止把执行资源控制、暂停命令、退让、限额施加到生产者。原因：生产者发现动态任务是独立责任，不能因执行压力受损。

### H3 生产者解耦可用性
生产者把发现工作与调度器可用性解耦：调度器停止接收、数据库暂不可写、回执未返回、执行全部暂停时，生产者仍持久化新发现任务并继续发布。原因：任务不丢失依赖生产者持久化，不能反过来被调度器拖累。

### H4 稳定作业标识
作业标识由（任务标识 + 稳定事件标识 + 业务版本）确定，重放/补扫得到同一 job_id。禁止每次随机生成。原因：去重与幂等依赖稳定标识。

实现算法（SDK `job_id_of`）：

```python
digest = sha256(f"{task_id}\0{event_id}\0{business_version}".encode()).hexdigest()[:32]
job_id = f"{task_id}-{digest}"
```

同一 (task_id, event_id, business_version) 重放/补扫得到同一 job_id。

### H5 无丢失发布
先持久化「发现游标 + 待发布记录」（同一原子写），再写临时文件 → fsync → 原子 rename → fsync 目录发布。成功后才标记已发布。原因：崩溃/重启窗口不丢事件，不产生半写 JSON。

### H6 生命周期只走协议
事件通道（进展/错误/完成/确认）+ 控制通道（暂停命令）+ 检查点文件 + 退出码。禁止自行删改 outbox / runtime 文件。原因：统一可观测、可恢复。

### H7 必走 SDK 契约
执行者继承 `ExecutorTask`，生产者用 `Producer`。禁裸脚本绕过断点/事件/退出码分类。原因：断点恢复/协作暂停/幂等提交是必需能力，靠 SDK 统一落地。

### H8 断点是任务可选实践，调度器不规定其维护方式
调度器不规定断点的文件名、格式、提交时机或存在性——是否断点、怎么断点、断点存什么，完全由任务自己决定。调度器仅在 run_dir 提供独立空间，且**不解析断点内容**；若任务写了断点文件，调度器在新 attempt 拉起前原样透传（便利而非强制）。恢复正确性由任务自己的幂等提交兜底——没有断点的任务重跑也不得产生重复结果。

### H9 凭证不入调度元数据，资源标识随信号上浮
不把接口/账号/凭证/密码/token 写入调度元数据或事件 reason（见 R5）；任务自行获得连接配置。**错误类型与资源标识（URL/主机/路径）按 R4 随 `error` 事件上浮**——调度器与运维据此归因，但不按资源身份做精细化调度决策（统一按资源不足退避/规避）。

### H10 源码不动、数据不手改
仅在调试清理时按流程编辑数据文件。禁止手改 `runtime/exec.db`、`runtime/runs/`、`producer_state/`。

### H11 子任务自包含
每个 `tasks/<id>/` 独享完整代码。禁止 `tasks/shared/` 或 `sys.path` 共享业务逻辑（SDK `sched_task_sdk` 除外）。

### H12 运行参数写在配置里，禁止文件名反推
进程跑什么（date/topic/query 等）必须写在就绪 JSON 引用的配置文件里（经 `input_refs` 或 `env` 引用）。禁止用 job_id 文件名反推参数。

### H13 及时打印进度日志
及时写 stdout/stderr（`flush=True`）并同步发进展事件，供运维观察；禁止静默长跑（长时间无进展事件）。

### H14 协作暂停而非强杀
执行者收到暂停命令后停止新工作、在安全边界自行保存进度（是否有断点由任务决定）、发 ack 再退出。不默认 SIGSTOP。生产者永不进入暂停流程。

## 外部资源纪律（R1–R9）

外部资源（代理隧道、目标站点、第三方 API 等）的身份、配额、限制均未知且随时间变化；任务间是否共用同一外部资源是随机的。调度器通过执行反馈（exit 75 事件流的密度与广度）自适应规避，任务侧遵守以下纪律：

### R1 不预设外部资源限制
不猜测 qps/并发/带宽上限，禁止实现任何预防性限速（并发槽、令牌桶、信号量）。外部资源今天限制 5qps、明天限制 1000qps，任何预设在另一个时刻都是错的。

### R2 不做任务间协调
禁止跨进程/跨任务的共享锁、共享计数、共享限速文件。任务间是否共用同一外部资源不可知，任何共享协调都会误伤不相关的任务。

### R3 资源错误有限重试，耗尽立即上浮
任务遇到外部资源不可得（检索/下载/网络/存储等资源类错误）时，对**单次外部操作**（一次请求 / 一次 CLI 调用）原地重试最多 **2 次**（固定短间隔 3s，仅过滤瞬时抖动——每次尝试都是新连接/新出口），仍失败立即抛 `Shortage` → exit 75 上浮调度器，由调度器统一决定退避、重排和并发调整。约束：

- **重试上限与间隔为固定常量**（如 `_MAX_RETRIES = 2`、`_RETRY_GAP_SEC = 3.0`），禁止指数退避、无界循环、自适应间隔——持续故障与瞬时故障的区分是调度器（按事件流密度）的职责，不是任务的职责；
- **每次重试必须打印日志**（保持可观测，防止"静默降速"式吞掉）；
- **业务事实不重试**：404/400/517 目标不可得、检索确认无数据（R6）直接走跳过/完成路径；
- **协作暂停不重试**：收到暂停请求后不得借重试延迟退出（重试间隔短，暂停延迟可忽略但不得叠加长等待）；
- **重试只作用于单次外部操作**，不作用于业务单元循环（禁止"对每个单元反复整体重跑"）。

### R4 上浮信息必须完整
`Shortage`（exit 75）/ `error` 事件的 reason 必须携带**错误类型**（异常类名 / HTTP 状态码 / 退出码）与**资源标识**（URL / 主机 / 对象路径），格式如 `TimeoutError: https://example.com/api（外部资源不可得）`。完整信息是调度侧归因与运维排查的依据。

### R5 上浮信息严禁凭证
reason 与事件字段中**严禁出现凭证**：账号、密码、token、API key、代理认证串。资源标识只到 URL/主机/路径级别；连接配置中的认证信息由任务进程自行持有，不进入调度元数据（与 H9 配合）。

### R6 空结果是业务事实
检索/查询结果为空时：间隔复核数次（如 5 × 60s）仍为空 → `complete({"count": 0, "reason": "检索确认无数据"})` 直接完成。禁止把"确实无数据"报成资源不足——那会造成无限退避，高优先级任务还会阻塞其他任务。

### R7 触发窗口留足外部数据滞后余量
外部数据源的公布存在批次延迟与索引尾巴（如 arXiv 每日批次最大滞后 4 天 + 索引 1 天），生产者触发窗口按最大滞后 + 余量设计（T-7），避免在数据未公布区间空转。

### R8 响应读取必须有总时长上限
socket 级超时（connect/read timeout）只保护"建立连接"与"字节间隔"，防不了坏出口的**慢速滴数据**：每 < timeout 间隔滴几个字节即可无限续命，进程表现为假活（进程正常、业务永久挂起在一个请求上）。任何响应 body 读取必须施加总时长上限（如 300s）：流式逐块读取 + 累计计时，超限即中断连接并按资源错误立即上浮（R3/R4）。

### R9 资源类错误必须上浮，禁止任何形式吞掉
资源类错误（超时、连接失败、代理错误、限流、截断、内容不完整等）在 R3 有限重试（2 次）耗尽后**必须立即上浮**。以下行为全部属于吞掉，一律禁止：

- **无界重试**：超出 R3 固定上限（2 次 × 3s）的任何重试循环（含"快速重试更多次""指数退避""失败N次后再等长间隔"）；
- **兜底**：失败后改用降级路径继续（如换备用数据源、降低质量重试）而不上报；
- **跳过**：把失败单元记入 failed/跳过名单继续处理后续单元（`_RecordSkip` 仅限"目标不可得"类业务事实——404、非 PDF 内容、撤稿——资源类错误不得走此路径）；
- **等待**：超出 R3 固定范围的自行等待重试（长 sleep、定时再探）；
- **静默降速**：吞掉失败、不发 `error` 事件或进展，让调度器在"看似健康、实则低效爬行"的状态下继续加压。

判断标准：**该错误是否意味着外部资源当前不可得？** 是 → 经 R3 有限重试仍失败则立即 `Shortage` 上浮（R3/R4）；否（目标本身不存在/内容非法）→ 业务事实，跳过或完成。

## 检查点真实性规则（C1–C2）

### C1 只在真实进展后提交检查点
检查点数据相对上次必须发生变化（新单元完成、计数增长）才提交。无变化数据重复落盘会产生检查点事件，被调度器误读为"外部已恢复"的证据，导致退避计数被错误重置、作业高频空转循环。

### C2 异常分支不保存未变化的断点
外部请求失败/异常穿透时，禁止保存自断点恢复后未变化的 done_ids 等数据——理由同 C1。

## 红线总表

| 编号 | 红线 | 违反后果 |
| --- | --- | --- |
| H1 | 绕过调度器自触发执行 | 失去资源协调与恢复保证 |
| H2 | 对生产者施加资源控制/暂停 | 破坏任务不丢失契约 |
| H4 | 随机生成作业标识 | 去重/幂等失效，重复执行 |
| H5 | 半写/未同步发布就标记成功 | 崩溃丢作业 |
| H7 | 裸脚本绕过 SDK | 无断点/暂停，无法恢复 |
| H8 | 任务依赖调度器理解/强制断点格式 | 调度器不规定断点维护，任务自己兜底幂等 |
| H9 | 把外部账号/凭证写入调度元数据 | 泄露 + 违反"本地不记录" |
| R1/R2 | 预设资源限制或任务间共享协调 | 跨资源误伤、并发语义失效 |
| R3 | 超出 2 次固定上限的重试/退避循环，或重试不落日志 | 瞬时/持续故障的区分被任务劫持，调度器规避滞后 |
| R5 | 凭证进入 reason/事件 | 凭证泄露 |
| R6 | 空结果报资源不足 | 无限退避，高优任务阻塞全局 |
| R8 | 响应读取无总时长上限 | 慢速滴挂起：进程假活，业务永久卡死 |
| R9 | 兜底/跳过/等待/静默降速吞掉资源错误 | 信号被藏，调度器误判健康持续加压 |
| C1/C2 | 无变化数据落检查点 | 退避判定被污染，作业空转循环 |

## 子任务开发契约（数据源不可回放的边界）

对于「短暂出现后永久消失、且数据源完全不保留」的事件，仅靠生产者无法在宕机期间恢复。此类数据源必须提供持久化事件日志、可靠订阅或独立缓冲，否则不能承诺任务永不缺失。生产者持续运行不能代替事件持久化。
