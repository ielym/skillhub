# 换服务器迁移指南

> 判断原则一句话：**服务器私钥变不变，决定客户端要不要全部重做。**

## 核心结论

| 类别 | 项 | 换服务器时 | 原因 |
|---|---|---|---|
| **必须修改** | 客户端配置 `Endpoint` | ✅ 改为新服务器公网 IP/域名 | 连接目标是服务器地址 |
| **必须修改** | 云安全组 | ✅ 在新服务器放行 UDP 51820 | 入站规则是云厂商资源 |
| **必须修改** | 服务器出口/NAT | ✅ 自动（install 检测默认网卡） | 新机器网卡名可能不同 |
| **可选：改** | 服务器密钥对 | ⚠️ 新建则**所有客户端必须重新导入** | 客户端校验的是服务器公钥 |
| **可复用** | 客户端密钥对（私钥/公钥） | ✅ 不用动 | 服务器只认客户端公钥 |
| **可复用** | 隧道网段 10.0.0.0/24、各设备 IP | ✅ 不用动 | 纯内网规划 |
| **可复用** | DNS、AllowedIPs、Keepalive 等客户端参数 | ✅ 不用动 | 与服务器无关 |

## 两种迁移策略

### 策略 A：保留服务器私钥（推荐，影响最小）

目标：**所有客户端只需改 Endpoint 一行**。

1. 新服务器重跑 `sudo wireguard-easy install <新IP>`
2. 把旧服务器的 `/etc/wireguard/server.key` 覆盖到新服务器同路径
   ```bash
   # 新服务器上
   cp server.key /etc/wireguard/server.key
   wg pubkey < /etc/wireguard/server.key > /etc/wireguard/server.pub
   systemctl restart wg-quick@wg0
   ```
3. 把旧服务器 `wg0.conf` 中所有 `[Peer]` 段追加到新服务器配置（或直接覆盖，注意新机器网卡名一致性）
4. 云安全组放行 UDP 51820
5. **每台客户端**：把 `.conf` 里 `Endpoint = 旧IP:51820` 改为 `新IP:51820`，重新激活即恢复

> 收益：服务器公钥不变 → 客户端配置无需重新生成/导入，只改一行。

### 策略 B：全新部署（最干净）

1. 新服务器 `sudo wireguard-easy install <新IP>`
2. 逐台 `sudo wireguard-easy add-client <设备名>` 重新生成配置 + 二维码
3. 每台设备重新导入新的 `.conf` / 扫码

> 代价：全部客户端重做；收益：无任何旧密钥残留，最干净。

## 新旧服务器并行切换（推荐操作顺序）

1. 新服务器部署完成、安全组放行、先用一台设备验证通过
2. 再逐个更新其余客户端 Endpoint（策略 A）/ 重新导入（策略 B）
3. 确认所有设备连上新服务器后，再释放旧服务器
4. 旧服务器密钥如已复制到新机，**旧服务器上的密钥文件应删除**（避免双活风险）

## 迁移检查清单

- [ ] 新服务器 `wg show wg0` 显示所有 peer
- [ ] 每台设备 `latest handshake` 在增长
- [ ] 每台设备 `ping 10.0.0.1` 通
- [ ] 每台设备 NAT 出口验证：访问 <https://api.ipify.org> 返回新服务器 IP
- [ ] 旧服务器已下线或密钥已清理
