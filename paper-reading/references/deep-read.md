# 论文精读

对**单篇论文**进行完整、可追溯且注重工程实践的精读。最终交付物是一篇结构完整的正式文档（兼容 Markdown 与飞书导入），而非阅读计划、简略摘要或零散问答。

## 输入处理

1. 优先使用用户提供的 PDF、正文、论文链接或准确标题。
2. 本地文件先确认存在并读取完整内容。
3. 链接则获取正文；正文引用关键附录或补充材料时一并读取。
4. 仅提供标题时，先定位标题、作者和版本一致的论文；存在同名或版本歧义且无法可靠消除时，向用户确认。
5. 代码仓库、模型卡和数据集页面只能补充复现信息，不能替代论文原文。
6. 检查是否存在与论文标题、作者和版本匹配的 OpenReview 页面。存在则完整阅读公开的 Official Review、作者回复、讨论、Meta Review 与最终决定（以实际存在内容为准），并整合到对应章节；未找到则在论文基本信息中说明。

## 阅读流程（三遍推进，不混读）

| 轮次 | 动作 | 产出（对应输出章节） |
|---|---|---|
| R1 框架轮 | 摘要 → 引言 → 各级标题 → 图 1 → 结论 → 扫参考文献；形成 5C 与研究问题 | §1 基本信息、§2 一句话总结、§3 背景 |
| R2 内容轮 | 逐节读方法；推演核心公式；逐张处理图表；抄录关键数字 | §5 方法、§6 实验、图表批判分析 |
| R3 批判轮 | 虚拟复现（用同样的假设重走一遍）；挑隐含假设；做"声称 vs 证据"对照；写批判问题 | §4 贡献、§7 复现、§8 局限、完成检查 |

**5C**：Category（什么类型的论文）/ Context（与哪些工作相关、理论基础）/ Correctness（假设是否成立）/ Contributions（贡献）/ Clarity（写得是否清楚）。R1 结束时应能回答全部 5 项。

## 阅读原则

- 阅读正文、图表、脚注及与核心结论有关的附录，不能只根据摘要作答。
- 以论文实际内容为准，不用领域常识替作者补充未披露的实现。
- 重要结论必须能追溯到页码、章节、公式、图或表。
- 明确区分并使用以下标签：

  - **\[论文事实]**：论文直接报告的方法、设置或实验结果。
  - **\[作者观点]**：作者对贡献、机制或结果的解释。
  - **\[评审观点]**：OpenReview 评审或元评审对创新性、正确性、实验和局限的判断。
  - **\[作者回复]**：作者在 OpenReview 回复或 rebuttal 中的解释、补充证据或承诺。
  - **\[AI 分析]**：执行本 skill 的 AI 基于证据给出的分析、质疑或推论，不代表用户已认可。

- OpenReview 属补充评议证据，不能替代原文。引用时标明评审类型，区分单个评审意见、评审共识、作者回复与最终决定；与论文证据冲突时展示分歧及双方依据，不自行判定为论文事实。
- 无法确认的信息标记为「论文未说明」，不得猜测。
- 对 PDF 页码，优先同时给出 PDF 页码与印刷页码；无法对应时说明采用哪一种。
- 数值比较必须核对指标方向、评测设置、模型规模、数据与计算预算是否可比。

## 输出结构

严格按以下九个章节展开。

### 1. 论文基本信息

- 标题、作者 / 机构、发表时间、会议或期刊、论文、代码与 OpenReview 链接；无匹配 OpenReview 页面时说明。
- 研究问题、应用场景、论文定位。
- 完整摘要及其中文翻译。
- 给出可信度评级（见下「可信度评级」）及一行为何给出该评级。

### 2. 一句话总结

用「解决了什么问题 + 用什么核心方法 + 得到什么结果」总结，隔一年仍能据此回想主要内容。

### 3. 研究背景与相关工作

- 论文要解决什么问题、为何重要、现有方法的主要路线。
- 现有方法的局限（尽量写成「方法 X 在条件 Y 下失败，因为 Z」，不只写「效果不好」），本文填补的空白、改进及其普适性。
- 本文与最相关工作的联系和本质区别。

### 4. 核心贡献与结论

- 作者声称的主要贡献与关键结论。
- 属理论贡献、算法贡献、工程贡献还是实验发现。
- 区分真正新东西与已有技术的组合 / 工程优化。
- 核对「作者声称的」与「实际支撑的」是否一致，指出 overclaim。
- 若有 OpenReview，纳入评审 / 元评审对贡献、新颖性及正确性的判断，结合作者回复分析争议是否解决。

### 5. 方法细节

- 默认假设、问题设定、输入输出。
- 模型结构或算法流程、模块间数据流。
- 用 Mermaid 绘制方法流程图，覆盖「输入 / 数据处理 → 核心模块 → 损失或输出」完整链路，连线上标注关键数据或张量；训练与推理有差异时分别绘制（按「图表批判分析」T1 的要求处理）。
- 逐条解释核心公式：符号、维度、假设；推导跨度大时补全中间步骤与依据；给出几何 / 概率 / 优化 / 信息论直觉。
- 训练目标、损失函数、优化策略、关键超参数、训练阶段。
- 数据构造、采样、配比、清洗过滤，数据集与 benchmark。
- 推理 / 部署特殊机制，计算复杂度、显存占用与延迟影响。

流程图必须反映论文实际方法，不得虚构模块、张量形状或训练步骤；缺失信息直接标注。

### 6. 实验分析

- 实验设置是否完整，baseline 与对比条件是否公平。
- 指标是否真实说明问题，是否报告方差、置信区间或多次运行。
- 消融是否充分，能否定位收益来源。
- 哪些结果最关键，提升幅度是否有实际意义。
- 是否存在反常结果、失败案例、负面结果或被弱化的问题。
- 泛化、鲁棒性、扩展性、效率实验是否充分且支持结论。
- 若有 OpenReview，纳入评审对实验充分性、基线公平性、结论可信度的质疑及作者回复的新增实验 / 解释。

### 7. 工程可复现性

- 代码、模型、数据、训练日志是否公开，许可证是否允许。
- 数据规模配比、算力、训练时长、训练配置、软件环境。
- 最小可行复现步骤、关键配置、验收指标与潜在陷阱。
- 实现难点，以及论文未披露但可能显著影响结果的细节。

### 8. 局限与风险

- 依赖的关键假设、适用边界与失效场景。
- 是否存在实验缺失、数据污染、基准泄漏或不公平对比。
- 数据、评测、训练 / 推理成本、稳定性、安全与合规风险。
- 区分作者明确承认的局限与 AI 分析得出的局限。
- 若有 OpenReview，补充评审 / 元评审指出且最终仍未解决的局限。

### 9. 输出与证据要求

- 重要判断标注页码 / 章节 / 公式 / 图 / 表，并使用【论文事实】【作者观点】【AI 分析】标注性质。
- OpenReview 判断给出页面链接与评审类型，用【评审观点】【作者回复】标注，不得写成【论文事实】。
- 无法确认的信息标记「论文未说明」，禁止自行补全。

## 图表批判分析

先把每张图 / 表打类型标签，再按对应类型逐项拷问。

| 类型 | 是什么 | 回答的问题 |
|---|---|---|
| T1 框架 / 架构图 | 方法总览、模块图、流程图 | 系统怎么搭、数据流怎么走 |
| T2 主结果表 | 与 SOTA / 基线对比的大表 | 是否更强、强多少 |
| T3 消融表 | 逐组件去掉的效果 | 增益来自哪个组件 |
| T4 效率 / 资源图 | 吞吐、延迟、显存、FLOPs、成本 | 代价是多少、用得起吗 |
| T5 缩放 / 敏感性曲线 | scaling、超参扫描、数据规模曲线 | 趋势是否单调、能否外推 |
| T6 定性可视化 | case、注意力图、生成样例 | 直观效果（最易 cherry-pick） |
| T7 分布 / 统计图 | 直方图、散点、箱线、混淆矩阵 | 数据分布与统计性质 |
| T8 数据 / 标注示例 | 数据构造、prompt 模板、标注规范 | 数据怎么造出来的 |

### 通用四问

1. 它在证明作者哪一 claim？找不到 → 标「装饰性图表」。
2. 轴 / 行列是什么、单位、范围？是否截断、是否对数轴？
3. 关键数值是多少？自行计算相对提升，不直接抄作者百分比。
4. 有无误差棒 / 多次运行 / 显著性？误差棒是 SD、SEM 还是 CI？完全没有或未说明 → 可信度降级。

### 逐类型细则

- **T2 主结果表**：抄录 3 行（最强基线 / 本文 / 同规模竞品）；自行算相对提升；核对摘要 vs 正文 vs 表格三处数字；看加粗规则（只有自己加粗且基线弱 → 可疑）；核查基线公平性（参数量 / 数据量 / 算力 / 评测设置）。
- **T3 消融表**：逐组件记录 Δ；定位主贡献组件并对照作者叙事；检查是否在多数据集 / 多规模上做。
- **T4 效率图**：硬件型号数量、框架版本、精度；batch / seq 长度、prefill / decode 是否分开；是否含固定开销；对比实现是否同等优化；吞吐与延迟（TTFT / TPOT）是否分别报告；显存峰值与 KV cache 假设。
- **T5 缩放曲线**：趋势是否单调、有无饱和反转；实测点个数、外推是否远超实测范围；横轴是否对数；能否外推到目标规模。
- **T6 定性可视化**：是否 cherry-pick（有无失败案例、是否随机采样、样本量）；找反例；定性结论不能单独作证据，须与 T2/T3 定量一致。
- **T1 框架图**：用 Mermaid 重画（不照搬原图），标注输入 / 输出张量形状、训练与推理差异、可训练 / 冻结模块；R3 时对照代码确认模块对应关系。
- **T7 / T8**：核对分布 / 统计口径是否合理；标注是否存疑。

图表以表格形式呈现时，结论需同时报告对比对象、指标、数据集与数值变化，不孤立摘录最优数字。

## 公式与图表要求

- 首次出现符号时定义含义、类型或维度。
- 推导按等式变换顺序展开并指出每一步依据，不用「显然 / 容易得到」跳过关键步骤。
- 公式很多时优先解释支撑核心贡献与结论的公式，次要公式可概述但不遗漏关键依赖。
- Mermaid 使用清晰可渲染的语法，节点名简洁，复杂说明放图后正文。

## 可信度评级

| 级 | 判据 |
|---|---|
| A | 顶会已接收或有权威背书；实验充分（多数据集 + 多规模 + 消融 + 误差棒）；开源代码与权重；结论保守 |
| B | preprint 但实验扎实、机构可信；或已接收但实验规模有限 |
| C | 基线偏弱 / 无误差棒 / 单一小规模验证 / overclaim / 无法复现 |
| D | 数字存疑、结论与数据不符、明显营销性表述 |

评级写入 §1，并据评级决定 §8 局限的审慎程度（C/D 需重点核对实验与结论）。

## 输出格式（飞书 + Markdown 兼容）

交付物必须同时可被 Markdown 渲染与飞书导入。若目标为飞书文档，写入依托 lark-doc skill，本子细则只约束内容格式：

1. 行内公式统一 `$...$`，独立公式统一单独成行 `$$...$$`。禁止 `\(...\)` 或 `\[...\]`。
2. 公式使用可稳定解析的基础 LaTeX；避免 `\underbrace{...}_{\text{...}}`、复杂自定义宏；符号含义另起正文说明。
3. 表格内公式也用 `$...$`，避免跨单元格、换行或复杂环境。
4. Mermaid 优先简单 `flowchart`、短节点名。若写入报错，简化后重试；仍失败则降级为 `text` 代码块或编号流程，不保留损坏占位块。
5. 写入后回读验证：标题、首末段、所有必需章节存在；公式无截断或解析残片；Mermaid 数量符合预期。细节回读流程走 lark-doc skill。

## 完成检查

交付前逐项确认：

**文档完整性**

- 已阅读支撑方法与结论所需的正文与附录。
- 九个章节均已输出；不适用或未披露的部分已说明。
- 方法流程图与正文一致，训练 / 推理差异已正确表示。
- 核心公式已解释符号、推导与直觉。
- 关键数值与结论均有原文定位，比较条件可比。
- 未把作者主张当成已被完全证明的事实。
- 未虚构链接、实现细节、实验结果或复现配置。
- OpenReview 已检查（存在则整合评审 / 作者回复 / 元评审 / 最终决定并标明未解决争议；不存在则已在 §1 说明）。

**理解质量（三条全中才可结束）**

1. 能讲：输出本身即在「问题 → 方法 → 证据 → 局限」上自洽、可被复述。
2. 能问：§8 已提出 ≥5 个批判问题，覆盖实验设计、方法假设、评测方式、外推性四个维度。
3. 能用：§7 已列出 ≥3 条可直接迁移的结论或方法要点，并明确其适用条件。

达不到「理解质量」时，说明缺口并继续补读或写明不确定原因，不得把未读当成已读。
