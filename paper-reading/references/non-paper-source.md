# 非论文来源解析

对**单条非论文来源**做结构化整理，覆盖博客、Release notes、代码仓库、榜单 / 评测、政策 / 标准、论坛帖、播客 / Newsletter 等。目标是提取可追溯的事实与可行动项，而非复述原文。

## 通用原则

1. **一手 > 二手**：厂商 blog / release notes / 源码 > 媒体报道。看到媒体的重大消息，先去查一手源再记。
2. **事实与观点分离**：分两栏记录——客观事实（版本号、时间、数字）vs 作者观点 / 推测。混写是日后误判主因。
3. **交叉验证**：重大信息至少两个独立来源；只有一个来源时标「未证实」。
4. **立场与利益标注**：谁说的、有何立场（厂商自吹 / 竞品踩 / 自媒体引流）。
5. **时效衰减**：记录必须写日期，并提示半衰期（release 以天计、榜单以周计、观点以月计）。
6. **可行动化**：每条结尾给出行动项（升级 / 试用 / 回看 / 忽略），没有行动项的内容不值得记。

## 按来源类型的关注点

| 类型 | 核心事实 | 常见陷阱 |
|---|---|---|
| 博客 / 观点文 | 主要论点、论据、结论 | 观点冒充事实、无数据支撑 |
| Release notes | 版本号、日期、变更项、兼容性破坏 | 忽略破坏性变更、遗漏已知问题 |
| 代码仓库 | 语言 / 许可证 / star / 版本 / 维护活跃度、README 要点 | 把 demo 当生产可用、忽略 license |
| 榜单 / 评测 | 指标定义、数据集、方法、排名字段 | 指标不可比、样例泄题、只报头部 |
| 政策 / 标准 | 发布时间、适用范围、条款要点、生效时间 | 断章取义、忽略适用范围 |
| 论坛帖 | 问题、讨论共识、多来源印证 | 以单帖当结论、未交叉验证 |

## 输出结构

结构化文档，字段随类型裁剪：

1. 元信息：标题、来源 URL、发布 / 上线日期、读取日期、类型标签。
2. 背景：这条信息为什么值得关注、对谁有价值。
3. 事实（分开列出）：可核实的客观内容，逐条标注来源位置。
4. 观点 / 推测（分开列出）：作者主张与立场，明确与事实区分。
5. 疑点与交叉验证：未证实内容、单一来源内容、利益相关方是否夸大。
6. 行动项：升级 / 试用 / 回看 / 忽略，并写明触发条件与日期。

## 输出格式

最终为 Markdown 文档，兼容飞书导入。非论文来源通常不含数学公式与 Mermaid；若确需图表，参考 [deep-read](deep-read.md) 的兼容规则。
